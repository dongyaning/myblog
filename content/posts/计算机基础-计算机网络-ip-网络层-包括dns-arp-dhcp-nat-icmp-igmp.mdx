MAC 直连结点通信，IP 就是非直连。

网络传输中，源/目标IP一直都不变（除非是NAT了），MAC一直在变。

基础的东西挺熟悉，简单说说。

# 分类地址

![image.png](<assets/IP-网络层(包括DNS,ARP,DHCP,NAT,ICMP,IGMP)-1.png>)

D、E 都没有主机号，不能分给主机。

多播：发送给特定组的所有主机。路由一般不转发广播（跨网段广播）。

分类网络简单明了，但是有明显缺点：

- 没有二级层次。
- C太少，B太多。

# 无分类地址 CIDR

就是两部分，不分类了。a.b.c.d/x。

可以由子网掩码对网段做子网划分。

# 公有IP和私有IP

![image.png](<assets/IP-网络层(包括DNS,ARP,DHCP,NAT,ICMP,IGMP)-2.png>)

记一下局域网地址的范围哈，这个还是能用到的。10开头，172（16-31），192.168开头

# IP地址与路由控制

目标IP -> 路由表中找 网络地址 的最长匹配，就是下一跳。

# IP分片与重组

以太网的MTU是 1500 B（别的可能不同）。 > 则 分片。

分片后，路由器不会重组，只有目标主机会重组。

这个分片尽量在TCP就做好，不要让内容超过 MTU。

# IPv6

128位，16个一组，十六进制表示，中间用 : 隔开。

![image.png](<assets/IP-网络层(包括DNS,ARP,DHCP,NAT,ICMP,IGMP)-3.png>)

## 亮点

- 首先最重要的肯定是长度更长了，由 32 位变成了 128 位。
- 自动配置，不需DHCP也能分配。
- 首部固定（取消选项字段），去掉包头校验和，简化首部结构，提高传输效率。
- 安全性提升。

# IP 相关协议

## DNS

这个在“网络传输流程概述”已经讲了哈。

## ARP

就是 IP -> MAC，广播 ARP消息，获得目标MAC并缓存。

### 补充：RAPR

就是反过来，MAC -> IP

比如说用于小型嵌入式设备，他不知道自己的IP，他就会问IP是啥，RARP服务器回复他。

## DHCP

![image.png](<assets/IP-网络层(包括DNS,ARP,DHCP,NAT,ICMP,IGMP)-4.png>)

就是**两个人都广播**，扯着嗓子喊，因为一开始还没有IP地址。

这里有一个问题，这全是广播，路由器不转发广播，DHCP不在服务器内就毁了。

但是针对DHCP可能是写了优化，路由器可以中继代理，可以发过去。

## NAT

就是局域网可以重复，局域网的所有主机用一个公网IP。但是这不行，用一个IP不就乱套了，NAT咋区分内网主机是哪一个？用端口来映射即可。就是把内网主机抽象成一个端口。

我说的有点绕，就是局域网内部的向外通信，NAT会抽象这个【主机，端口】到【公网，端口】，并把这个映射记录下来。回来的时候，对方肯定认为是【公网，端口】发的，他的目的地址也会是这个，就可以查NAT转换表再映射回去了。

NAT 不光可以缓解 IPv4 地址资源短缺的问题，还可以隐藏内部网络的实际拓扑结构，使得外部网络无法直接访问内部网络中的设备，从而提高了内部网络的安全性。

## ICMP

Internet Control Message Protocol，互联网控制报文协议。

遇到问题了，传出个消息，其他人好调整传输策略。

**主要功能：确认IP包是否成功送达目标地址、报告发送过程中IP包被废弃的原因和改善网络设置等。**

![image.png](<assets/IP-网络层(包括DNS,ARP,DHCP,NAT,ICMP,IGMP)-5.png>)

大致分为两类：

1.  诊断的查询信息，查询报文类型。
2.  通知出错原因的错误消息，差错报文类型。

## IGMP

和 ICMP 没关系哈！

组播不是要发到某一组吗，这个就是管理组的。工作在 【主机和最后一跳路由之间】。

就是路由器周期性发送查询，主机报告成员关系，路由器记录组关系。

主机离开的时候向路由器报告，路由器发送查询，更新组关系或删除组。
