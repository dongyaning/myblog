几个技巧题要记住。

第一个是**只出现一次的数字**，这个是异或运算。

第二个是**多数元素**，使用投票法，第一个元素作为众数候选者，遇到一样的就times--，相当于投反对票。times为0就更换候选者，times再更新为1。

第三个是**颜色分类**，相当于对只有三种元素的数组排序，要求仅一次扫描。使用双指针。像类似这种使用双指针对数组处理的，记住要交换，而不是直接赋值，直接赋值带来的后果很难处理，如果把元素交换到后面，在遍历的时候还可以再遍历到，那么就不用担心。如果把元素交换到后面再遍历的时候遍历不到了，那么就需要对这个数据多加关注，确保一次性可以到位，不会出现错误。回到这个题目。

```java
双指针方法有很多，这里使用首尾指针的方式，其它的思考方式类似，即首指针p0处理0，尾指针p2处理2.
初始化：p0 = 0, p2 = n-1
具体算法：

从前到后遍历nums
1).如果nums[i]为0，则交换nums[i]与nums[p0]，p0自增
2).如果nums[i]为2，则交换nums[i]与nums[p2]，p2自减

因为是从前到后遍历，所以1)是没问题的，把0放到前面，是绝对正确的，以后再也不用处理它了。
但是对于2)来说，把nums[p2]交换到i的位置之后，i就自增了，谁知道这个nums[p2]是0，1或2，并且
以后也不会再处理它了，就可能会产生错误。
所以我们需要把这个问题处理好，处理方式就是如果换过来的值是2，就继续交换nums[p2]，如果是0，就
使用1)的处理方式。如果是1，则暂时不用处理，因为虽然后面不会再遍历这个1，
但是如果1不是正确位置，后面一定还有0，还会交换。

结束的条件是 i > p2，p2+1到末尾的位置已经确定是2了，再遍历就错了。
```

第四个是**下一个排列（全排列的下一个排列）**，要求O(1)的空间复杂度。全排列的思路就不适用了，因为空间复杂度达不到要求。这个题目的核心是思路，问题转化。首先，下一个排列一定是要比当前排列的字典序大的，所以我们需要找一个字典序更大的，就需要在左边找一个小数，在右边找一个大数，交换一下。同时，我们也希望变大的幅度尽可能地小，所以我们希望这个小数尽可能地靠右，这个大数尽可能地小。由这两个思路，我们找到最靠右的两个满足大小关系的数对，进行交换，这里还要注意，要保证变大的幅度尽可能地小，在交换完之后，我们还需要对原小数位置右边的元素进行排序。这个一定是没问题的，因为左边的数变大了，右边一定是升序的时候才是最小的排列情况。

```java
在寻找这么一个数对时，一种想法是使用两层循环，从后向前遍历小数，如果右边有比它大的数，就选出来比较小的。
还有一种想法是先从后往前找到第一个i,i+1数对第满足nums[i]<nums[i+1]，此时i+1后边一定是降序。所以只需要
从右到左找到第一个大于i的j就可以了。同时，此时，因为i后面一定是降序，所以排序也就变成了reverse。
```

第五个是寻找重复数，将这个题目转化为链表成环问题非常巧妙，因为一定有重复数字，所以如果建立i->nums[i]的边，一定有两个不同的点都可以走到同一个nums[i]，一定会成环。这里nums[i]一定就相当于从i走了一步。成环问题使用快慢指针解决，要找到出口就由a = c，慢指针设为0，与快指针同时走，相遇点即为入环点，也就是答案。注意，快慢指针的相遇点是环中的任意点，未必是入环点。
