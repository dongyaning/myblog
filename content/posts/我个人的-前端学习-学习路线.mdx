- `EventEmitter` 事件总线

#### 1.2 必须理解的原理

**事件循环（Event Loop）**

```javascript
// 经典输出题 - 必须能解释
console.log('1')
setTimeout(() => console.log('2'), 0)
Promise.resolve().then(() => console.log('3'))
console.log('4')
// 输出顺序: 1, 4, 3, 2

// 流程: 同步代码(1,4) → 微任务队列(3) → 宏任务(2)
```

**原型与原型链**

- 构造函数、实例、原型的关系
- `__proto__` 与 `prototype` 的区别
- 原型链查找机制

**闭包**

```javascript
// 闭包经典题
for (var i = 0; i < 5; i++) {
  setTimeout(() => console.log(i), 1000)
}
// 输出: 5, 5, 5, 5, 5

// 解决方案1: let
for (let i = 0; i < 5; i++) {
  setTimeout(() => console.log(i), 1000)
}

// 解决方案2: IIFE
for (var i = 0; i < 5; i++) {
  ;(function (j) {
    setTimeout(() => console.log(j), 1000)
  })(i)
}
```

**ES6+ 模块化**

- CommonJS vs ESM 区别
- 加载方式：运行时 vs 编译时
- 输出特性：值的拷贝 vs 值的引用

**WeakMap/WeakRef 与垃圾回收**

### 模块2：React深度

> 面试占比：~35%  
> 重点：架构原理 + Hooks底层 + 性能优化

#### 2.1 React核心架构

**Fiber架构（必考）**

- 为什么需要Fiber：解决递归遍历虚拟DOM无法中断的问题
- Fiber节点结构：链表结构（child/sibling/return）
- 双缓存机制：current树 + workInProgress树
- 时间切片：利用浏览器空闲时间执行任务
- 优先级调度：高优先级任务可打断低优先级

```javascript
// Fiber节点简化结构
{
  type,           // 组件类型
  stateNode,      // DOM节点或组件实例
  child,          // 第一个子Fiber
  sibling,        // 下一个兄弟Fiber
  return,         // 父Fiber
  pendingProps,   // 新props
  memoizedProps,  // 旧props
  memoizedState,  // 状态
  effectTag,      // 副作用标记
}
```

**虚拟DOM与Diff算法**

- 虚拟DOM的作用：减少直接DOM操作、跨平台
- Diff策略：

1.  只比较同层级节点
2.  type不同直接替换整棵子树
3.  通过key识别节点移动

- 为什么React不比原生JS快：虚拟DOM有额外开销，但提供了声明式开发体验

**setState机制**

```javascript
// React 18自动批处理
function handleClick() {
  setCount((c) => c + 1)
  setFlag((f) => !f)
  // 只触发一次重渲染（React 18）
  // React 17中异步回调内不会批处理
}

// setState异步的原因
// 1. 性能优化：合并多次更新，减少重渲染
// 2. 一致性：确保状态在同一时刻是确定的
```

**合成事件系统**

- 事件委托：所有事件绑定在root节点
- 合成事件：抹平浏览器差异
- 为什么要自己实现：性能优化 + 跨平台

#### 2.2 Hooks原理（必考）

**useState 闭包陷阱**

```javascript
function Counter() {
  const [count, setCount] = useState(0)

  useEffect(() => {
    const timer = setInterval(() => {
      setCount(count + 1) // ❌ 永远是0+1（闭包捕获旧值）
      setCount((prev) => prev + 1) // ✅ 使用函数式更新
    }, 1000)
    return () => clearInterval(timer)
  }, []) // 依赖为空，只执行一次
}
```

**useEffect vs useLayoutEffect**

- useEffect：在浏览器绘制后异步执行
- useLayoutEffect：在DOM更新后同步执行（阻塞渲染）
- 使用场景：需要测量DOM时用useLayoutEffect

**useMemo vs useCallback**

```javascript
// useMemo：缓存计算结果
const expensiveResult = useMemo(() => heavyCompute(data), [data])

// useCallback：缓存函数引用
const handleClick = useCallback(() => doSomething(id), [id])

// 区别：useMemo返回值，useCallback返回函数
// 常用场景：useCallback通常配合React.memo使用
```

**useRef**

```javascript
// 场景1: 保存DOM引用
const inputRef = useRef(null)
;<input ref={inputRef} />

// 场景2: 保存可变值（不触发重渲染）
const countRef = useRef(0)
countRef.current++ // 修改不会触发重渲染

// 场景3: 保存定时器ID用于清理
const timerRef = useRef(null)
```

**自定义Hooks**

- 本质：复用状态逻辑
- 必须以`use`开头
- 每次调用都有独立的状态

#### 2.3 React 19新特性（了解）

- **Actions**：简化异步操作处理
- **use() Hook**：在条件和循环中读取Promise
- **Server Components**：服务端渲染组件
- **React Compiler**：自动优化，减少手动useMemo/useCallback

#### 2.4 状态管理方案

| 方案                 | 适用场景     | 特点                   |
| -------------------- | ------------ | ---------------------- |
| Context + useReducer | 轻量全局状态 | 内置，无需额外依赖     |
| Zustand              | 中小型项目   | 简单、轻量、无Provider |
| Redux Toolkit        | 复杂大型项目 | 生态完善、DevTools强大 |
| Jotai/Recoil         | 原子化状态   | 细粒度更新             |
| React Query          | 服务端状态   | 缓存、重试、无限滚动   |

#### 2.5 高频React场景题

- 如何实现10万条数据不卡顿（虚拟列表原理）
- React中循环渲染为什么不用index做key
- 如何避免Context引起的整棵树重渲染
- React.lazy懒加载原理
- 如何实现类似Vue的keep-alive功能
- React Router和原生History路由的区别
- 函数组件和类组件的区别
- React性能优化手段汇总

### 模块3：CSS与浏览器

> 面试占比：~15%  
> 重点：布局 + 动画 + 浏览器原理

#### 3.1 CSS必会

**布局**

```css
/* Flex布局 */
.container {
  display: flex;
  justify-content: center; /* 主轴 */
  align-items: center; /* 交叉轴 */
}

/* flex: 1 等价于 */
.item {
  flex-grow: 1; /* 放大比例 */
  flex-shrink: 1; /* 缩小比例 */
  flex-basis: 0%; /* 基础大小 */
}

/* Grid布局 */
.grid {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 10px;
}
```

**居中方案（至少5种）**

```css
/* 1. Flex */
.parent {
  display: flex;
  justify-content: center;
  align-items: center;
}

/* 2. Grid */
.parent {
  display: grid;
  place-items: center;
}

/* 3. 定位 + transform */
.child {
  position: absolute;
  top: 50%;
  left: 50%;
  transform: translate(-50%, -50%);
}

/* 4. 定位 + margin: auto */
.child {
  position: absolute;
  top: 0;
  right: 0;
  bottom: 0;
  left: 0;
  margin: auto;
}

/* 5. 定位 + calc */
.child {
  position: absolute;
  top: calc(50% - height/2);
  left: calc(50% - width/2);
}
```

**BFC（Block Formatting Context）**

- 触发条件：overflow不为visible、float不为none、position为absolute/fixed、display为inline-block等
- 作用：阻止margin合并、清除浮动、包含浮动元素

**CSS3动画**

```css
/* 翻牌效果 */
.card {
  transform-style: preserve-3d;
  perspective: 1000px;
}
.card-front,
.card-back {
  backface-visibility: hidden;
}
.card-back {
  transform: rotateY(180deg);
}
.card:hover {
  transform: rotateY(180deg);
}

/* transition vs animation */
/* transition: 需要触发条件，只有两个状态 */
/* animation: 可自动播放，支持多关键帧 */
```

**移动端适配**

- rem方案：根据屏幕宽度动态设置html font-size
- vw/vh方案：直接使用视口单位
- 媒体查询：针对不同屏幕尺寸写不同样式

#### 3.2 浏览器原理

**渲染流程**

```plain
URL输入 → DNS解析 → TCP连接 → HTTP请求 → 服务器响应
→ 解析HTML → DOM树 → 解析CSS → CSSOM树
→ 渲染树 → 布局(Layout) → 绘制(Paint) → 合成(Composite)
```

**重排(reflow) vs 重绘(repaint)**

- 重排：元素几何属性变化（宽高、位置），触发重新布局
- 重绘：元素外观变化（颜色、背景），不触发重新布局
- 重排一定触发重绘，重绘不一定触发重排
- 优化：批量修改DOM、使用transform代替top/left

**缓存策略**

| 缓存类型 | 控制字段                | 特点                  |
| -------- | ----------------------- | --------------------- |
| 强缓存   | Cache-Control / Expires | 不发请求，直接用本地  |
| 协商缓存 | ETag / Last-Modified    | 发请求验证，304用本地 |

```nginx
# 最佳实践
# HTML: 协商缓存
Cache-Control: no-cache

# 带Hash的JS/CSS: 强缓存1年
Cache-Control: max-age=31536000
```

**跨域解决方案**

1.  CORS（最常用）：服务端设置Access-Control-Allow-Origin
2.  代理：开发环境用webpack/vite proxy
3.  JSONP：只支持GET，利用script标签
4.  WebSocket：不受同源策略限制

**HTTPS握手过程**

1.  客户端发送支持的加密算法
2.  服务端返回证书和选定的算法
3.  客户端验证证书，生成随机数
4.  双方根据随机数生成对称密钥
5.  使用对称密钥加密通信

### 模块4：工程化与性能优化

> 面试占比：~15%  
> 重点：构建工具 + 性能优化体系

#### 4.1 构建工具

**Vite vs Webpack**

| 对比项 | Vite        | Webpack    |
| ------ | ----------- | ---------- |
| 冷启动 | 1-2秒       | 30-60秒    |
| HMR    | 50-100ms    | 1-3秒      |
| 原理   | ESM原生支持 | 打包bundle |
| 适用   | 新项目首选  | 老项目维护 |

**Webpack核心考点**

```javascript
// splitChunks配置
module.exports = {
  optimization: {
    splitChunks: {
      chunks: 'all',
      cacheGroups: {
        vendors: {
          test: /[\\/]node_modules[\\/]/,
          name: 'vendors',
          priority: 10,
        },
        commons: {
          minChunks: 2,
          priority: 5,
        },
      },
    },
  },
}
```

- **Loader vs Plugin**：Loader是转换器，Plugin是扩展器
- **Tree Shaking**：ES Module静态分析，移除未使用代码
- **SourceMap**：映射压缩代码到源码，便于调试
- **HMR原理**：WebSocket通知 + 模块热替换

#### 4.2 性能优化体系

**加载优化**

- 代码分割：路由级、组件级懒加载
- CDN：静态资源分发
- 预加载：preload / prefetch
- 压缩：gzip / brotli
- Tree Shaking：移除死代码

**渲染优化**

- 虚拟列表：只渲染可视区域
- 防抖节流：控制高频事件
- requestAnimationFrame：动画优化
- Web Worker：耗时计算移出主线程

**缓存优化**

- HTTP缓存：强缓存 + 协商缓存
- Service Worker：离线缓存
- localStorage / sessionStorage：数据缓存

**监控指标（Core Web Vitals）**

| 指标 | 含义         | 目标值     |
| ---- | ------------ | ---------- |
| LCP  | 最大内容绘制 | &lt; 2.5s  |
| FID  | 首次输入延迟 | &lt; 100ms |
| CLS  | 累积布局偏移 | &lt; 0.1   |

**高频场景题**

- 10万条数据渲染不卡顿
- QPS峰值处理
- 全站请求耗时统计
- 首屏加载白屏优化
- 前端监控方案设计
- 大文件切片上传

## 五、高频场景题

### 必须掌握的场景题

1.  **10万条数据渲染不卡顿**

- 虚拟列表：只渲染可视区域DOM
- 时间分片：requestIdleCallback分批渲染
- 分页/懒加载：最常规方案

- 防抖节流：限制事件频率
