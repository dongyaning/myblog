# 全局锁

```sql
flush tables with read lock // 整个数据库就只读了

unlock tables // 放开锁
```

一般用于数据库备份，但是加了全局锁就导致业务停滞，对于支持可重复读的存储引擎，可以使用 --single-transaction开启事务，在Read View上操作。

# 表级锁

## 表锁

```sql
// 共享锁，读锁。当前会话读取，其他不能写。注意哈，自己加锁之后就只能读这个，不能读其他的表
lock tables t read
// 独占锁，写锁。当前会话读写，其他不能读写
lock tables t write
// 释放
unlock tables
```

## 元数据锁MDL

这个实际上就是表的结构的锁，不需要自己手动开启，我们对表CRUD会自动加上MDL读锁，修改表结构会加上MDL写锁。

如果有一个长事务一直持有MDL读锁，别的事务要修改表结构就会被阻塞。而写操作优先于读操作，后面的读操作也都会被阻塞（本来读读是不互斥的），所以尽量避免这种情况，可以kill掉长事务再修改表结构。

## 意向锁

**意向锁的目的是为了判断表里是否有记录被加锁。**

对于增删改操作，会对记录加行级独占锁，在这之前先对表加意向独占锁。

对于查询操作，会对记录加行级共享锁，在这之前先对表加意向共享锁。

如果没有意向锁，加独占表锁的时候就要遍历表里的全部记录看看有没有锁，就会很慢。

有了意向锁，就可以看看有没有人已经加了意向锁，有的话就说明存在行级锁。

## AUTO-INC锁

这个就是为了自增主键设计的锁，插入数据时其他的插入被阻塞。但是会影响性能，mysql5推出了一个轻量版的，就是不会等到插入完才释放锁，而是分配好id就释放锁，可以配置用哪一个。

当使用轻量锁，也就是 innodb_autoinc_lock_mode=2，且binlog的格式为statement时(记录原始的语句)，主从库会出现数据不一致。解决方式就是binlog_format设置为row。

因此，**最佳实践：innoodb_autoinc_lock_mode = 2 & binlog_format = row**

# 行级锁

## Record Lock

就是行级锁，锁一个记录，也分为共享锁（S锁）和独占锁（X锁），只有S和S是兼容的。

## Gap Lock

间隙锁，存在于可重复读和串行化隔离级别，目的是为了解决可重复读隔离级别下幻读的现象。

比如有(3, 5)的间隙锁，其他事务就无法插入id为4的记录。

间隙锁之间是兼容的，两个事务可以持有相同范围的间隙锁，效果是一样的，都是不能在这个范围插入数据。

## Next-Key Lock

临键锁，Record Lock + Gap Lock。锁住一个范围和记录本身。

## 插入意向锁

这个是针对 insert 语句的，插入之前加一个插入意向锁，但是插入意向锁是一个软锁，不互斥，不是为了阻止别的事务插入，而是表明“我想插入这个位置”。如果这个区域存在间隙锁，也会被阻塞，但是加这个锁的作用是告诉存储引擎，“我是在等间隙锁释放”，“我的目的是向这个位置插入数据”。

插入意向锁和同一区间的间隙锁不能同时存在的意思是说，如果这个区间有间隙锁，再请求插入意向锁就会被阻塞了，会等着锁释放。也就是说插入意向锁和间隙锁是互斥的，只有持有了插入意向锁，才可以执行插入。所以这个意向锁，容易引起误会，“一旦拿到了意向锁，就表明可以插入了，反而不是表达的一种意向”。

# MySQL如何加锁（行级锁）

![image.png](/images/posts/后端学习-mysql-锁篇/锁篇-2.png)

**加锁的对象是索引，加锁的基本单位是 next-key lock**，由记录锁和间隙锁组合而成，next-key lock 是前开后闭，间隙锁是前开后开。

普通的快照读是不加锁的，通过MVCC控制

```sql
select ... lock in share mode; -- 共享锁
select ... for update; -- 独占锁
```

在能使用记录锁或者间隙锁就能避免幻读现象的场景下，next-key-lock会退化为记录锁或间隙锁。

下面来分类讨论。

## 唯一索引 & 等值查询

注意这里是以主键索引举例的，对于非主键的唯一索引，除了要锁上二级索引，还要对主键索引也加上记录锁。

### 查询的记录存在

那就退化为记录锁即可，因为这样就能解决幻读问题。因为主键是唯一的，用的还是等值查询，只要把这一条记录锁上，下一次执行相同的语句就一定是一样的，别的事务不能改也不能删这个记录。

所以这里要特别注意哈，幻读说的是“前后两次执行同一个查询记录数量不同”，两次查询是完全相同的。

### 查询的记录不存在

这里要特别注意一点哈，就是前面说的加锁的对象是索引，这个索引得存在才能加记录锁。

要两次查一个不存在的数据都返回不存在，又没法加记录锁，就只能加间隙锁了，锁住这个间隙，虽然有“误伤”存在。

同时，又没必要加next-key，因为查的是不存在的，要幻读下次也得查这个，和后面的记录没有关系。

## 唯一索引 & 范围查询

反正就是让幻读不发生就行，具体讨论如下，这都比较细节和特异性。

### 大于

这里要注意哈，间隙锁就是锁一个间隙，锁相邻的两个id，如果要锁多个区间就是加多个锁。

比如说要查x，大于很显然就是把(x +oo\] 都锁上，这个+oo的实现是innodb在最后有一个这样的id，叫supremun pseudo-record。

### 大于等于

如果=的那个记录存在，就是记录锁+大于条件的n个间隙锁。

如果不存在，那就是从查询的元素前面的一个id开始的n个间隙锁。这是很显然的。

**小于和小于等于也是类似的哈，我就不具体说了，反正就是自己想的怎么加能防止幻读，就是怎么加的。**

## 非唯一索引 & 等值查询

这里先讲一下，在执行的时候是怎么判断有没有被锁的。是**通过在B+树上查找到查询记录位置的后面位置**（如果查询的记录存在，那就是记录本身），看这个元素上是不是有锁，所以看的是后面一个元素的状态。

从下面这个锁上也可以看出来，记录的是next-lock锁（包括间隙锁）的右端点：

![image.png](/images/posts/后端学习-mysql-锁篇/锁篇-3.png)

这个时候，对于主键索引还好，都是唯一的，不用考虑索引值相同的情况。

但是对于非唯一索引就要考虑这个问题了，除了要对非唯一索引加锁，还要对主键加锁，来规避幻读问题。

### 记录不存在

比如对age，现在有10，22，39，50

要for update查 age = 25的这个记录，这是不存在的。首先肯定要对age索引加上(22, 39)的间隙锁。

但是单纯这样还不行，因为就像我上面说的，判断是否加锁是看的后面一个元素的状态。二级索引是按照二级索引值按顺序排放的，二级索引相同会按主键顺序排。

我们现在是在age=39的第一条记录上加的锁，我们要保证这个记录是age=25这个查询后面的第一条记录，不能是再有一个age=39的插到这个记录的前面（id比之前的小），所以我们除了要加这个间隙锁，还要对主键加锁，插入的主键id不能小于当前的这个最前面的记录id，往后面插可以。

![image.png](/images/posts/后端学习-mysql-锁篇/锁篇-4.png)

后面的20就是记录的 id。

### 记录存在

一定要记住哈，**一切的加锁都是为了防止幻读**。同时，对于非唯一索引的间隙锁，锁的也是一条记录，而不是所有的age = x的记录，是在一条记录上加的锁，而且判断的时候，是判断的查询的记录位置的后面一个位置。所以才会有看似没必要的设计。

对于记录存在的情况，比如22，就是加一个(21, 22\] 和一个 (22, 39)，你只要理解了我上面说的，应该就能懂为什么这么加。加锁是针对一条记录加锁的，是（二级索引，主键索引）的组合，要防止两次查询22都是一样的，那么就要做到：不能插前面，也不能插后面。

## 非唯一索引 & 范围查询

比如 slect \* from t where age >= 22 for update;

加锁：(21, 22\], (22, 39\], (39, +oo\]

理解了上面的，理解这个是很容易的。

## 没有索引的查询

因为是全表扫描，所以会对每一个记录都加上next-key lock，相当于把全表锁了，而且不只是读，delete, update等也是一样的。所以一定要避免这个问题，where 条件要加索引。

## 补充

间隙锁、记录锁等不只是对插入生效，对更新和删除也可以。

InnoDB 的行锁是针对索引字段加的锁，表级锁是针对非索引字段加的锁。当我们执行 `UPDATE`、`DELETE` 语句时，如果 `WHERE`条件中字段没有命中唯一索引或者索引失效的话，就会导致扫描全表对表中的所有行记录进行加锁。这个在我们日常工作开发中经常会遇到，一定要多多注意！！！

# 死锁

![image.png](/images/posts/后端学习-mysql-锁篇/锁篇-5.png)

这个情况会死锁（没开死锁检测），因为两个当前读都会持有(1006, +oo\] 的锁，间隙锁是不互斥的，因为间隙锁的目的就是保证没有事务能在这个间隙插入数据。

## 死锁避免

死锁的四个必要条件：

- 互斥
- 占有且等待
- 不可强占用
- 循环等待

可以通过如下方式避免：

1.  设置事务等待锁的时间，一个事务等待超过这个时间就回滚，另一个事务就可以执行了。参数 innodb_lock_wait_timeout 用来设置超时时间，默认50秒。
2.  开启主动死锁检测，检测到死锁发生后，主动回滚一个事务。innodb_deadlock_detext 设置为on.
3.  业务层面，比如上面的两个当前读的目的就是幂等性校验，不出现重复订单，那么可以直接对订单号设置唯一索引。
