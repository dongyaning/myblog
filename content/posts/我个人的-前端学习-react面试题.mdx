# 你怎么做 React 性能优化？

按以下层次来说：

1.  预防：保证组件结构合理，状态尽量下放。（因为状态越靠近叶结点可能影响的组件就越少）
2.  减少计算：复杂计算用 useMemo，稳定的函数用 useCallback
3.  避免冗余渲染：React.memo 配合稳定的 props；大列表里必用虚拟列表。
4.  利用 Nextjs 的 SSG/SSR 解决首屏加载慢的问题；利用 Suspense 做代码分割。

# React 的 Hooks 底层原理

**为什么 hooks 必须写到顶层，不能写到 if 块里？**

这在本质上是为了**确保 hooks 执行顺序的绝对确定性**。

React 内部，每个 Fiber 节点都有一个属性叫 **memoizedState**，对于函数组件，这个属性存的是一个**单向链表**。

React 的 hooks 相当于排队领盒饭，hooks 和 状态的关联完全靠先后顺序，如果先后顺序改变，就会造成状态乱套。

# React 合成事件

合成事件的关键点有两个：委派 和 抹平。

这个委派其实就是委派给父节点，在 React17 以后，这个父节点由 document 变为了 React 容器的根节点、这个可以防止在很多个结点上创建一样的时间监听器，节省内存。绑定到容器根节点可以解决多个 React 应用嵌套时的冒泡冲突问题，也让 React 能够更好地集成到微前端架构中。

同时，React 相当于封装了一层抽象，可以抹平不同浏览器的差异，向用户提供要统一的接口。

# React 渲染流程

**编译 -> 协调 -> 提交**

**编译阶段：**

JSX -> 虚拟 DOM，通过 \_jsx 函数调用。

虚拟 DOM 本质上就是一个普通的 JS 对象。

**协调阶段（核心）：**

虚拟 DOM -> 新 Fiber 树

React 会**对比旧 Fiber 树和新虚拟 DOM 哪些地方变了（Diff）**。基于工作循环，把任务拆成一个个微小的单元，每过一段时间（16ms）检查一下是否有优先级更高的任务，最后输出一棵被打上了“增删改”标记的 Fiber 树。

**提交阶段：**

Fiber 树 -> 真实 DOM

React 遍历带有标记的 Fiber 树，调用 DOM 原生 API 操作 DOM。

同步且不可中断，一口气完成。
