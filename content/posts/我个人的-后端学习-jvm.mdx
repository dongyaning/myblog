JVM的职责是运行Java字节码文件。

三大核心为：内存管理、解释执行虚拟机指令、即时编译。

![image.png](/images/posts/我个人的-后端学习-jvm/jvm-1.png)

# 字节码文件

## 基本信息

### Magic魔数

这里插补一下，计算机文件的后缀名实际上是方便识别和默认处理软件的。改了后缀名并不会改变文件内容。文件是什么类型的是根据文件内容开头（有的也要看结尾）的特定字符指示的。而字节码文件的指示字符就叫做魔数。CAFEBABE

### 版本号

字节码也是有版本号的，就是里面的数字减去44。运行的时候需要字节码的版本和当前的JDK匹配。当前JDK版本高是可以的，但是不能比字节码文件的版本低。

出现冲突的时候一般是改变依赖的版本，而不是升级JDK，因为后者操作更重。

### 其它

访问标识、父类、接口等。

## 常量池

保存字符串常量、类或接口名、字段名。这里保存字符串常量是通过字段->字符串->字符串字面量。因为常量池里面除了保存字符串字面量还要保存字段名，可能存在重复。如果是字段名就是字段->字符串字面量，这样可以区分开。

## 方法

这里的方法说的是“字节码指令”。这个东西类似于汇编语言，是JVM自己设计的一套东西。通过案例来了解一下。

![image.png](/images/posts/我个人的-后端学习-jvm/jvm-2.png)

像是一般的赋值操作，都是需要先把那个字面量放到操作数栈里面，在操作数栈中运算完之后再把对应的值放到局部变量表中。比较特殊的是++操作，是直接通过一条iinc指令修改局部变量表中的值。

考虑下面的情况：

```java
int i = 0;
i = i++;
```

运行这个程序，i最后的值为0。这是因为整体是赋值操作，所以先把i的值放到操作数栈中，再执行++操作，但是++操作是直接针对局部变量表的，后面从操作数栈到局部变量表的store操作会把+1覆盖掉。

++i是可以成功加上的，因为是先iinc，后iload。

## 加载

类加载器根据类的全限定名通过不同的渠道以二进制流的方式获取字节码信息。加载完类之后，Java虚拟机会将字节码中的信息保存到方法区中。 生成InstanceKlass对象，保存类的所有信息，里面还包含实现特定功能比如多态的信息。

同时，JVM还会在堆中生成类似的java.lang.Class对象，用于反射等特性。这个对于开发者是开放的，数据量少于方法区中的类信息。

## 连接

### 验证

检查字节码文件是否符合JVM规范，如：

- 文件格式（例如魔数），主次版本号是否合适。
- 元信息，如每个类必须有父类。
- 验证语义逻辑。
- 是否访问了private。

### 准备

做一些特殊处理，如final修饰的变量直接赋值。

### 解析

将常量池中的符号引用转换为内存地址引用，不再使用编号，提高效率。

## 初始化

- 执行静态代码块中的代码，并为静态变量赋值。

```java
public class Demo {
    static {
        value = 2;
    }
    public static int value = 1;
    // 最后结果为1，字节码执行顺序与Java代码书写顺序一致。
}
```

- 执行字节码文件中clinit部分的字节码指令。

- clinit初始化的是静态变量，如果没有或者静态变量都是final修饰，就不执行。

### 初始化触发条件

- 访问一个类的静态变量或者静态方法，注意变量是final修饰的并且等号右边是常量不会触发初始化，因为这个变量已经在连接阶段处理过了。
- 调用Class.forName(String className)方法
- new 一个对象
- 使用Main方法中的当前类

### 题目

```java
public class Test1 {
    main() {
        sout("A");
        new Test1();
        new Test1();
    }

    public Test1() {
        sout("B");
    }

    // 这个是构造代码块，逻辑上在构造函数的前面执行。
    {
        sout("C");
    }

    static {
        sout("D");
    }
}

// 结果：DACBCB
```

### 继承条件下

- 访问父类的静态资源，不会调用子类的clinit。
- 调用子类clinit前，会先调用父类的clinit。
