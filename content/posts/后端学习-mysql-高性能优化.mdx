# MySQL 性能怎么优化？

MySQL 性能优化是一个系统性工程，涉及多个方面，在面试中不可能面面俱到。因此，建议按照“点-线-面”的思路展开，从核心问题入手，再逐步扩展，展示出你对问题的思考深度和解决能力。

## 抓住核心：慢 SQL 定位与分析

找到瓶颈，具体可以通过：

- 监控工具，如 MySQL 慢查询日志，Performance Schema 等。

```sql
SET GLOBAL slow_query_log = 'ON';
SET GLOBAL long_query_time = 1; -- 建议设为 1 秒或更低
SET GLOBAL log_queries_not_using_indexes = 'ON'; -- 记录未用索引的查询

mysqldumpslow：官方自带，汇总慢日志（如按平均时间排序）。
pt-query-digest（Percona Toolkit）：更强大的分析工具，生成详细报告。
```

```sql
UPDATE performance_schema.setup_consumers
SET ENABLED = 'YES'
WHERE NAME LIKE 'events_statements%';

原理：MySQL 内置的性能监控框架，以表形式暴露运行时性能数据。
关键表：
events_statements_history_long：历史 SQL 语句及耗时。
events_statements_summary_by_digest：按 SQL 模板（digest）聚合统计
                  （执行次数、平均延迟、全表扫描次数等）。
```

- EXPLAIN 命令，分析查询计划、索引使用情况。

## 架构优化

- **读写分离：** 将读操作和写操作分离到不同的数据库实例，提升数据库的并发处理能力。
- **分库分表：** 将数据分散到多个数据库实例或数据表中，降低单表数据量，提升查询效率。但要权衡其带来的复杂性和维护成本，谨慎使用。
- **数据冷热分离**：根据数据的访问频率和业务重要性，将数据分为冷数据和热数据，冷数据一般存储在低成本、低性能的介质中，热数据存储在高性能存储介质中。
- **缓存机制：** 使用 Redis 等缓存中间件，将热点数据缓存到内存中，减轻数据库压力。这个非常常用，提升效果非常明显，性价比极高！

## 其它

- 连接池配置：连接池大小、超时时间等。
- 硬件配置：使用高性能服务器、增加内存、使用 SSD 硬盘等硬件升级，都可以有效提升数据库的整体性能。

# 深度分页（大偏移分页）问题

## 场景

**使用 LIMIT 时的查询流程：\*\***边查边计数 offset，offset 到了再返回指定的行数 n。\*\*

当查询偏移量过大时，MySQL 的查询优化器可能会选择全表扫描而不是利用索引来优化查询。这是因为扫描索引和跳过大量记录可能比直接全表扫描更耗费资源。

其实上面这句话说的有歧义哈，就算是用索引也只会更慢。**核心就是要查询 offset + n 次**，offset 大了性能肯定不好。

## 深度分页问题优化

### 基于游标

适用于：下一页分页模式，不支持直接跳转到很后面的情况。

思想：不适用 offset，而是记录上一页的最后一条的位置。先利用索引优化范围查询，再对后面的 n 条数据遍历返回即可。

```sql
-- 第一页
SELECT * FROM orders ORDER BY id LIMIT 10;

-- 假设最后一条 id = 100
-- 第二页：查询 id > 100 的前 10 条
SELECT * FROM orders WHERE id > 100 ORDER BY id LIMIT 10;

-- 第三页：假设上一页最后 id = 205
SELECT * FROM orders WHERE id > 205 ORDER BY id LIMIT 10;
```

### 产品设计优化

限制用户最多翻到 100 页，大部分的场景都是可以的，一般没有这个强需求。

### 使用专门的分页表活冗余字段

预计算行号，适用于数据变化不频繁，但是需要深度翻页的场景。
