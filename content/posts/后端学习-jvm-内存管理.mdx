## 程序计数器PC（线程私有）

保存下一个指令的内存地址。

⚠️ 注意：程序计数器是唯一一个不会出现 `OutOfMemoryError` 的内存区域，它的生命周期随着线程的创建而创建，随着线程的结束而死亡。

## 虚拟机栈（线程私有）

方法调用的数据需要通过栈进行传递，每一次方法调用都会有一个对应的栈帧被压入栈中，每一个方法调用结束后，都会有一个栈帧被弹出。

栈由一个个栈帧组成，而每个栈帧中都拥有：局部变量表、操作数栈、动态链接、方法返回地址。和数据结构上的栈类似，两者都是先进后出的数据结构，只支持出栈和入栈两种操作。

![image.png](/images/posts/后端学习-jvm-内存管理/内存管理-3.png)

Java 方法有两种返回方式，一种是 return 语句正常返回，一种是抛出异常。不管哪种返回方式，都会导致栈帧被弹出。也就是说， **栈帧随着方法调用而创建，随着方法结束而销毁。无论方法正常完成还是异常完成都算作方法结束。**

### 局部变量表

存放局部变量和返回地址等。

### 操作数栈

存放执行指令过程中的临时数据。

### 动态链接

指向运行时常量池，可以实现多态。因为像是普通的成员方法存在多态，在编译器没法确切知道实际的调用方，需要在运行时动态分派。

设计虚方法调用时就会用到动态链接，如多态、接口方法调用、父类方法被子类重写。

对于 static、private、final 方法，在编译时就可以确定类型，就是静态分配。

### 运行时动态链接过程：

```java
class Animal {
    public void speak() {
        System.out.println("Animal speaks");
    }
}

class Dog extends Animal {
    @Override
    public void speak() {
        System.out.println("Woof!");
    }
}

public class Main {
    public static void main(String[] args) {
        Animal a = new Dog(); // 多态：父类引用指向子类对象
        a.speak();            // 这里会用到动态链接！
    }
}
```

编译 Main.class，a.speak()生成的字节码：invokevirtual #5

当 main 执行到 a.speak()，JVM 创建 speak 对应的栈帧。

栈帧中的 **动态链接** 部分会：

- 查看 `a` 的实际类型（`Dog`）
- 在 `Dog` 类的方法表中查找 `speak()` 的实现
- 将常量池中的符号引用 `#5`（指向 `Animal.speak`）**动态解析为** `**Dog.speak**` **的直接地址**

## 本地方法栈（线程私有）

和虚拟机栈类似，只不过是虚拟机栈是执行Java方法，也就是字节码。本地方法栈是执行native方法。

## 堆

线程共享。

分为三个区域：used, total, max.

堆内存不足时，会增大total，直至total = max。堆的内存整体是比较大的。

**此内存区域的唯一目的就是存放对象实例，几乎所有的对象实例以及数组都在这里分配内存。**

先把握整体结构：

![image.png](/images/posts/后端学习-jvm-内存管理/内存管理-4.png)

新生代：Eden，Survivor（S0, S1）

老年代：Old

Java7 有永久代，在堆内存中。

Java8 移除了永久代，功能迁移至元空间，元空间不属于堆，使用本地内存（Native Memory）。

新创建的对象一开始在Eden，Eden满了触发Minor GC，回收新生代，新生代还存活的放入Survivor，年龄+1。

两个Survivor区域是等大小的，总有一个是空的。

新生代年龄达到阈值默认15（最大值也是15，因为是四个二进制位管理的），就放入老年代。

老年代满了，触发Major GC，回收老年代。

## 方法区

线程共享。

逻辑概念，就是说JVM定义了有这么个东西，存放什么数据，具体怎么做，没指定，由具体虚拟机实现。

方法区是存放基础信息的位置，主要包括：

类的元信息，运行时常量池，字符串常量池。

方法区的存储位置在JDK 7之前和JDK 8之后是有区别的：

- JDK 7之前的方法区存放在堆内存的永久代中，属于直接由JVM管理的内存范围。堆的大小由虚拟机参数-XX: MaxPermSize = 值来控制。
- JDK 8之后的方法区存放在元空间中，元空间位于操作系统的直接内存，默认情况下，只要不超过操作系统上限可以一直分配。通过-XX: MaxMetaspaceSize = 值来限制。

以上的讨论是基于HotSpot虚拟机。

![image.png](/images/posts/后端学习-jvm-内存管理/内存管理-5.png) 永久代(&lt; 8) 和 元空间(>= 8) 相当于是具体实现。

元空间位于本地内存中，如果不指定，只受限于操作系统，可能耗尽所有的系统资源。

### 本地内存（& JVM的内存的真实整体结构）

JVM会向操作系统预申请一大块虚拟内存（只是告诉操作系统需要这么多内存，不真的占这么多物理内存），分为堆和非堆。

JVM的内存申请不是一次性的，而是按需，分阶段，动态地向操作系统申请内存。

**JVM 实际上就是一段 C++ 程序，那些什么这区那区都是逻辑概念**，到程序上其实就是一个内存分配的事。这都是设计上的东西。

比如说线程里面的那些东西，虚拟机栈啥的，就是要创建的时候新建一个线程，才有的那些空间。

**所谓的堆和非堆，在C++程序层面来说，是没有区别的，都是向操作系统申请内存。**

**区别在于：JVM的管理方式和使用方式**。

| **维度**                                         | **Java 堆（Heap）**                             | **非堆（Non-Heap / Native Memory）**                                                |
| ------------------------------------------------ | ----------------------------------------------- | ----------------------------------------------------------------------------------- |
| **用途**                                         | 存放 **Java 对象实例**（`new Object()`&lt;br>） | 存放 **JVM 自身运行所需的数据**                                                     |
| **使用者**                                       | **Java 应用程序代码**                           | **JVM 内部（C++ 代码）**                                                            |
| **分配方式**                                     | JVM 自己管理（TLAB、指针碰撞）                  | 调用 OS API（`mmap`&lt;br>, `malloc`&lt;br>）                                       |
| **回收机制**                                     | **垃圾回收器（GC）自动管理**                    | **手动管理或间接回收**                                                              |
| **生命周期**                                     | 随对象生命周期变化                              | 随类加载、线程、NIO Buffer 等变化                                                   |
| **OOM 类型**                                     | `Java heap space`                               | `Metaspace`&lt;br>/ `Direct buffer memory`&lt;br>/ `Unable to create native thread` |
| **是否受\*\*** **`-Xmx`&lt;br>\*\*\*\***控制\*\* | ✅ 是                                           | ❌ 否                                                                               |

**“堆”和“非堆”（包括元空间、线程栈、直接内存等）在物理上都是 JVM 这个 C++ 程序向操作系统申请的内存，没有天然区别；  
\*\***但为了**管理方便、职责清晰、性能优化和错误隔离\*\*，JVM 在设计上**人为划分了不同的逻辑区域\*\*，并赋予它们不同的名字、用途和管理策略。\*\*

### 运行时常量池

主要保存字面量（数字），还有类名，变量名，方法名等符号引用。这个在JDK 8以后也在元空间。

运行时常量池是Class文件常量池的运行时表示，Class文件常量池是编译期生成的常量和符号。

每个.class都有一个常量池，运行时常量池是这个常量池活的版本，运行时使用。

运行时常量池包含：一个类在运行时所需的 名字字典 + 常量表

### 字符串常量池

本来是运行时常量池的一部分，在JDK 7以后没有放入元空间，而是在堆中，所以和运行时常量池分离开来。

## HotSpot虚拟机对堆中对象的管理（分配、布局、访问）

### 对象的创建

**类加载检查。**虚拟机遇到一条 new 指令时，首先将去检查这个指令的参数是否能在常量池中定位到这个类的符号引用，并且检查这个符号引用代表的类是否已被加载过、解析和初始化过。如果没有，那必须先执行相应的类加载过程。

**分配内存。**把一块确定大小的内存从Java堆中划分出来。方式有指针碰撞和空闲列表。指针碰撞要求内存得连续，规整。前面是已分配的，后面是未分配的，在已分配的后面连续分配即可。空闲链表就是维护一个空闲块链表，找到大小合适的。

创建对象需要是线程安全的，保证方式有CAS（乐观锁的一种）+失败重试 和 TLAB（每个线程预分配，分配的用完了再使用CAS+失败重试）。

**给除了对象头的部分全部初始化为0。**

**设置对象头。**存储这个对象是哪个类的实例、如何才能找到类的元数据信息、对象的哈希码、对象的 GC 分代年龄等信息。

**执行init。**构造函数啥的。

### 对象的内存布局

三个部分：**对象头（Header）**、**实例数据（Instance Data）和对齐填充（Padding）**。

对象头：

- 标记字段（Mark Word）：用于存储对象自身的运行时数据， 如哈希码（HashCode）、GC 分代年龄、锁状态标志、线程持有的锁、偏向线程 ID、偏向时间戳等等。
- 类型指针（Klass pointer）：对象指向它的类元数据的指针，虚拟机通过这个指针来确定这个对象是哪个类的实例。

对齐填充：Hotspot 虚拟机的自动内存管理系统要求对象起始地址必须是 8 字节的整数倍。

### 对象的访问定位

栈中有一个reference字段，指向的内容有两种实现方式：句柄 和 直接引用

句柄就是维护一个句柄池，reference指向句柄池。

直接引用，就是reference直接指向真实对象的地址。
