# 事务的特性

- 原子性：这个就是事务是一个整体，要么都成功，要么都失败

- undo log 回滚日志

- 一致性：执行事务前后总状态不变，如总余额，一个合法状态到另一个合法状态

- 持久性 + 原子性 + 隔离性，也就是说其它三个满足了，一致性就满足了

- 隔离性：不同事物之间不互相影响

- MVCC / 锁机制

- 持久性：提交了对数据的修改是永久的，故障也不可丢失

- redo log 重做日志

# 隔离性

## 并发事务存在的问题

- 脏读：一个事务读到了另一个事务未提交的数据。
- 不可重复读：一个事务内多次读取同一数据，前后不一致。
- 幻读：一个事务内多次查询某个符合查询条件的记录数量，前后不一致。

严重性从上到下递减。

MySQL 并发控制的方式无非两种：锁和 MVCC，锁可以看作是悲观控制模式，MVCC 是乐观控制模式。

## 四种隔离级别

![image.png](/images/posts/后端学习-mysql-事务篇/事务篇-1.png)

串行化就是加锁。

MySQL InnoDB的默认隔离级别为 可重复读，也能在很大程度上避免幻读现象，不是完全避免，是因为：

- 对于快照读，普通slect，通过MVCC方式
- 对于当前读，通过next-key lock方式，记录锁 + 间隙锁，在一个范围内不让插入。

读提交和可重复读都是 Read View 实现的，区别在于创建快照的**时机**。读提交是每次语句执行前都会重新生成一个Read View，可重复读是启动事务的时候生成一个Read View，一直用这个。

# Read View（MVCC 实现）

read view 中的四个字段：

![image.png](/images/posts/后端学习-mysql-事务篇/事务篇-2.png)

快照记录上面这些信息，再配合记录中保存的隐藏字段 trx_id 和 roll_pointer。

trx_id 指向的是最后操作这个记录的事务id，roll_pointer 指向的是上一个版本的 undo日志。

对于一条记录，可以分为如下几种情况：

1.  对于自己操作的记录，可见。
2.  如果记录的trx_id小于min_trx_id，那就是已经提交过了，可见。
3.  如果trx_id大于等于max_trx_id，那就是在快照之后才创建的事务操作的，不可见。
4.  如果trx_id在min_trx_id和max_trx_id之间的话，

5.  如果trx_id，在m_ids中，那就是还没提交，不可见
6.  如果不在，那就是提交了，可见

**这种通过「版本链」来控制并发事务访问同一个记录时的行为就叫 MVCC（多版本并发控制）。**

**基于以上 Read View 结构，读提交和可重复读的不同也只是快照创建时机问题。**

## 幻读问题

**ANSI SQL-92 的幻读定义：**

幻读：同一事务中，两次执行**相同的范围查询**，第二次**多出了其他事务插入的行**。

MySQL 可重复读隔离级别下，不会出现这种标准的幻读。注意这个标准幻读指的是：“**完全相同的查询，且多出了其他事务插入的\*\***原始行\*\*”。

对于 读 -> 写 -> 读的场景，虽然会看到其它事务插入的行，但是这个行也是被自己修改过的，可见是合理的，这不算是标准的幻读，算是一种边界情况，说是幻读也行，网上说的不能完全解决幻读就是类似的情况。
