# url -> 网页显示流程（知识串联）

## 浏览器解析URL

![image.png](/images/posts/计算机基础-计算机网络-网络传输流程概述/网络传输流程概述-1.png)

有了域名和资源链接，就可以封装HTTP报文了。

封装报文之后，因为要交给操作系统发送到对应的网口，所以这个时候就得通过DNS获取对方服务器的IP地址了。

## DNS

实际上域名最后还有一个点，比如 `www.server.com.`，这个最后的一个点代表根域名。

DNS服务器是一个分层结构：

- 根域名服务器
- 顶级域名服务器
- 权威域名服务器

### DNS解析过程

先查浏览器缓存，再查操作系统缓存，再找hosts文件，都没有再找本地DNS服务器（本机配置的）。本地DNS服务器如果不知道，就去问根域名服务器，根域名服务器给本地域名服务器响应顶级域名服务器的地址。本地域名服务器问顶级域名服务器，顶级域名服务器再给权威域名服务器的地址，再问权威域名服务器，权威域名服务器给出IP地址给本地域名服务器，发给主机并缓存。

现在可以调用系统调用发送报文了，这个时候数据包应该去找谁呢？

## 协议栈

我们使用的通用操作系统，如Windows, Linnix，macOS，都会实现完整的TCP/IP协议栈，协议栈作为内核或内核模块的一部分，提供 socket API 给应用程序使用。

**实现内容包括**：

- 网络接口层（驱动 + 链路协议如 Ethernet、Wi-Fi）
- IP（IPv4/IPv6）、ICMP、ARP
- TCP、UDP
- 常用应用层协议的支持（通过用户态程序，如 DNS 解析库）

像是路由器也运行专用的OS，必须实现完整的协议栈，二层交换机一般只实现链路层协议。

![image.png](/images/posts/计算机基础-计算机网络-网络传输流程概述/网络传输流程概述-2.png)

## TCP 可靠传输

三次握手，双方主机维护一个状态机，也就是建立连接了。

如果消息过长，超过了MSS，TCP就需要把HTTP的数据拆解成一块块的数据发送，而不是一次性发送所有数据。

![image.png](/images/posts/计算机基础-计算机网络-网络传输流程概述/网络传输流程概述-3.png)

MTU：一个网络包的最大长度，以太网一般为1500B。

MSS：TCP数据的最大长度。(一般在传输层分片，尽量不要 IP 分片，因为网络层没有重传，丢一个就得发送对应 TCP 的全部 IP 分段)。

现在，数据包已经加上TCP头部了，可以实现可靠传输，下一步应该由IP出场了。

## IP 远程定位

如果有多个网卡，就会去路由表匹配，如果匹配不到，就会走到默认网关位置，由路由器来转发。

之后加上IP头，现在数据包已经加上了 TCP 头，加上了 IP 头，下一步去哪？当然是链路层协议。

## MAC 两点传输

源MAC地址在网卡的ROM里，但是目的MAC还不知道。这个时候就要通过ARP广播了，ARP就是IP -> MAC的协议。

ARP协议广播：“sei嘞IP，你嘞mac地址是啥”。对方就会回答：”我嘞，我嘞mac地址是xxx“。之后会把这个mac地址缓存的。

OK，现在套娃套了三层了，该发了吧！

## 网卡 出口

要让数据在电线上传输，得是电信号，总不能在电线里边发01吧。这就是网卡的工作，而网卡由网卡驱动程序控制。网卡驱动获取套娃后的网络包，将其复制到网卡内的缓冲区，在其开头和结尾加上帧信息。

![image.png](/images/posts/计算机基础-计算机网络-网络传输流程概述/网络传输流程概述-4.png)

- 起始帧分界符表示包起始位置
- 末尾的FCS用来检查包传输过程是否有损坏

最后，网卡将包转换为电信号，通过网线发送出去。

发出去了！

## 交换机 送别者

电信号到达交换机的网线接口，交换机内部的模块将电信号转换为数字信号。通过FCS校验错误，没问题就放到缓冲区。要注意，交换机的端口没有MAC地址。

接下来查询接收方MAC是否已经在MAC地址表中有记录了。

交换机的MAC地址表信息主要是两个：

- 设备的MAC地址
- MAC地址对应的交换机端口

如果找不到就会广播到除源端口外的所有端口，收到回复再缓存下来。

OK，这个时候交换机找到了默认网关，也就是路由器的MAC地址，就可以转发给路由器了。

## 路由器 出境大门

- 路由器是基于IP协议的，三层设备，每个端口都有MAC地址和IP地址。
- 交换机是基于以太网的，二层设备，端口不具备MAC地址，更别说IP地址了。

路由器只接受和自己地址匹配的包（MAC地址），遇到不匹配的包直接丢弃。

MAC头部的作用就是将包送到路由器，送到之后，MAC头的任务就完成了，就会被丢弃（后面还得再套一个新的）。

之后查询路由表，确定转发端口。

![image.png](/images/posts/计算机基础-计算机网络-网络传输流程概述/网络传输流程概述-5.png)

第三个 0.0.0.0 是默认路由，这个过程也是目标地址和掩码做&，然后和destination对比，选择一个合适的端口转发出去。这里有两个情况：

- 表中的网关是一个IP，那说明还没到目标网段，还得转发给下一个路由器。
- 表中的网关为空，那就是到目标网段了，可以发给目标主机了。

知道下一跳的IP地址之后，通过ARP查询MAC地址（如果没有缓存），再包上MAC头尾，网卡驱动，数字信号转电信号，发送...

此时，数据包通过多个路由器道友的帮助，在网络世界途经了很多路程，最终抵达了目的地的城门！城门值守的路由器，发现了这个小兄弟数据包原来是找城内的人，于是它就将数据包送进了城内，再经由城内的交换机帮助下，最终转发到了目的地了。

## 服务器与客户端 互相扒皮

数据包到达服务器，服务器开始扒皮，跟拆快递似的。扒MAC头，看看是不是自己的。再扒IP，看看是不是自己。根据IP头部，知道内部协议是TCP。扒开TCP，里面有序列号，如果是要的就放到缓冲区，返回一个ACK。TCP还有一个端口号，HTTP服务监听这个端口号。

HTTP服务器解析出来一看，是要找xxx资源，把这个资源封装起来，上协议栈套上TCP，IP，MAC头，数字信号转电信号，发给交换机，交换机发给路由器，路由器发给目标网段，发到客户端。客户端扒皮，给浏览器，浏览器再把页面渲染出来。

客户端要走了，TCP四次挥手，说再见...
