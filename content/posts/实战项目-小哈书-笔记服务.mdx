关于Redis双写一致性，不可能保证完全一致性，每个方案都是有可能出问题的。但是一般来说，

先更新数据库后删除缓存的方案是比较好的，在此基础上可以加上优化方案（大厂实践）。

1.对于高并发，一致性要求没有特别高的场景，可以使用消息队列解耦+异步删除缓存

也就是说，数据库先删掉，然后push消息队列，消费者再删除缓存，对于高并发友好。

2.Canel / Debezium 等监听数据库日志（Binlog）

这个是大厂常用方案，

- 业务代码无感知
- 不怕应用崩溃导致缓存未删
- 更可靠

```plain
MySQL → Canal → RocketMQ → Cache Cleaner Service → 删除 Redis 缓存
```

这个方案算是比较优秀的了，建议使用。
