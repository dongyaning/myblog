# 进程和线程

进程：计算机中正在运行的一个程序实例。

线程：轻量级进程，多个线程可以在一个进程中同时执行，共享进程的资源比如内存空间，文件句柄，网络连接等。

## 为什么有了进程还需要线程？

核心原因是要实现低开销、高效率的并发。线程相比进程来说：

- 线程更轻量，进程切换开销大。
- 同一进程内的线程共享内存和文件，他们之间通信无需调用内核。而进程之间通信就很麻烦。

## 为什么要使用多线程？

核心就是 高并发 + 提高 CPU 利用率（多核比较直接，单核可以应对 IO 密集型任务）。

## 线程间同步方式

加锁（互斥锁、读写锁、信号量（信号量其实也算是锁））、屏障（一种同步原语，用于等待多个线程到达某个点再一起继续执行）、事件（wait/notify）；

## 进程状态

和线程差不多，少了 BLOCKED（因为没有多进程同步问题，不需要阻塞状态），RUNABLE 分成了两个（进程层面上，ready 和 running 分的就比较开）。

![image.png](/images/posts/计算机基础-操作系统-进程管理/进程管理-1.png)

## PCB（Process Control Block，进程控制块）

操作系统管理和跟踪进程的数据结构，每个进程对应一个独立的 PCB。

当进程执行时，PCB 中的信息会不断变化，操作系统会根据这些信息来管理和调度进程。

PCB 主要包含下面几部分的内容：

- 进程的**描述信息**，包括进程的名称、标识符等等；
- 进程的**调度信息**，包括进程阻塞原因、进程状态（就绪、运行、阻塞等）、进程优先级（标识进程的重要程度）等等；
- 进程**对资源的需求情况**，包括 CPU 时间、内存空间、I/O 设备等等。
- 进程**打开的文件信息**，包括文件描述符、文件类型、打开模式等等。
- **处理机的状态信息**（由处理机的各种寄存器中的内容组成的），包括通用寄存器、指令计数器、程序状态字 PSW、用户栈指针。
- ……

# 进程间通信方式（重要）

内核空间是进程共享的，所以要**通过内核实现进程通信**。

## 管道

有匿名管道和命名管道（FIFO），看名字也看出来，管道是先入先出的。

通信效率低，不适合频繁通信。

### 匿名管道

匿名管道就是 Linux 里面用的那个 | ，就相当于内存中的一个缓冲区，一个假文件。

创建：

```java
int pipe(int fd[2])
```

注意：匿名管道只适用于父子进程之间（兄弟也行，反正得都复制那个文件描述符），因为这是一个假文件，是一个进程创建出来的（**父进程创建了两个文件描述符，在管道两边，所以父子进程和星弟进程可以通信**）。而这个进程创建子进程就可以复制文件描述符，父子进程一人用一个就可以通信了。

管道单独构成一种独立的文件系统：管道对于管道两端的进程而言，就是一个文件，但它不是普通的文件，它不属于某种文件系统，而是自立门户，单独构成一种文件系统，并且只存在于内存中。

**管道的实质是一个内核缓冲区，顺序写，顺序读，可以看做一个循环队列，一个数据只能读一次。**当缓冲区读空或者写满时，有一定的规则控制相应的读进程或者写进程进入等待队列，当空的缓冲区有新数据写入或者满的缓冲区有数据读出来时，就唤醒等待队列中的进程继续读写。

管道只能一端写入，另一端写出。所以父子进程的两个fd要各自关一个。

![image.png](/images/posts/计算机基础-操作系统-进程管理/进程管理-2.png)

执行 | 命令时，两个进程都是shell的子进程，所以也可以通信。

### 命名管道

为了克服管道（匿名管道）只能用于亲属之间通信的局限。

这个是真的创建了一个文件，所以可以用于没有关系的两个线程之间。

```shell
mkfifo myPipe

echo "hello" > myPipe

cat < myPipe
```

## 信号

信号是软件层次上对中断机制的一种模拟，一般就是内核或其他进程通知用户进程用的机制，异步通知。

一旦有信号发生，进程有三种方式响应信号：执行默认操作、捕捉信号、忽略信号。

**信号可以用于进程间通信（IPC），但它是“最原始、最粗糙”的 IPC 方式，仅适合发送“通知”（如“快停下！”），不适合传递数据。通信的双方是：一个用户进程（发送者）和另一个用户进程（接收者），但信号的传递必须经由内核中转。**

如shell进程 kill 用户进程，就是通过内核发送一个信号。信号都是这样的固定的一些指令，代表特别的意思，不适合那种定制度高的场景。

## 消息队列

和rocketmq那玩意差不多，只是操作系统内核实现的。消息队列是保存在内核中的消息链表。

问题是：

- 不适合传比较大的数据。
- 传数据的时候，因为这个队列在内核，需要把数据从用户 拷贝->内核，取的时候再拷贝出来，存在开销。

## 共享内存

一般情况下是不同进程的虚拟空间（即使虚拟地址一样） -> 不同的物理空间。现在可以拿出来一块来映射到相同的物理空间，就可以用这个通信了，是最快的可用 IPC 形式。

- 为了在多个进程间交换信息，内核专门留出了一块内存区，可以由需要访问的进程将其映射到自己的私有地址空间。进程就可以直接读写这一块内存而不需要进行数据的拷贝，从而大大提高效率。

![image.png](/images/posts/计算机基础-操作系统-进程管理/进程管理-3.png)

## 信号量

就是共享内存做同步，相当于加锁。

## Socket

就是网络编程，不同主机之间的进程通信。这里将的是进程间通信，不仅限于相同主机之间。

# 进程调度

当CPU空闲时，操作系统选择内存中某个【就绪状态】的进程，将其分配给CPU。

先总结说一下调度算法：

- 先来先服务
- 最短作业优先
- 高响应比优先
- 时间片轮转
- 最高优先级
- 多级反馈队列

## 先来先服务

比较简单，就是按顺序一个一个来，前面的执行完了或者阻塞了，下一个才允许。

看似公平，但是如果前面是长作业就坏了。后面全阻塞了。

## 最短作业优先调度

这个就是第一种的另一端，很可能把长作业饿死。

## 高响应比优先调度算法

就是一种权衡，既考虑到任务本身的长度，又考虑到任务的等待时间。

## 时间片轮转调度

最古老、最简单、最公平、使用最广。

经验来看，将时间片设置为 20ms - 50ms 是一个比较合理的折中值。

## 最高优先级调度算法

就是赋予进程优先级，可以是静态，也可以是动态。

但是也存在问题，也可能会饿死低优先级的进程。

## 多级反馈队列调度算法（现实最常用）

多级队列，前面的优先级高，时间片短。（队列内部FIFO，第一次没执行完就放到后面队列的队尾）

只有前面的队列执行完了，才会执行后面的。

新的进程来了，就放到第一个队列末尾。

如果在后面的执行过程中，有新的进程进入较高队列，就把当前正在运行的放入对应队列队尾，然后先去执行更高优先级的。

- 对于短任务，可能第一次执行就结束了。
- 对于长任务，也不会饿死，因为前面的进程执行是时间有限的。

这个算法兼顾了长短作业，同时有较好的响应时间。

# 僵尸进程和孤儿进程

前置知识：

Unix/Linux 系统中，当一个进程执行 exit() 时，内核会释放该进程的所有资源，包括打开的文件、占用的内存等，但是！PCB依然存在于内存中。需要父进程 wait() 或 waitpid() 释放。

**僵尸进程（Zombie Process）的出现，不是因为操作系统“忘了”删除 PCB，而是出于一个非常重要的设计目的：让父进程有机会获取子进程的退出状态（exit status）**。

**僵尸进程：**子进程已经终止，父进程仍在运行，父进程没有调用 wait() 或 waitpid() 系统调用来回收子进程。

**孤儿进程：**一个进程的父进程已经终止，但是该进程仍在运行。通常是意外终止，未及时调用 wait() 或 waitpid() 回收子进程。操作系统会将孤儿进程的父进程设置为 init 进程，由 init 进程来回收孤儿进程的资源。

linux 可使用 top 命令查找，zombie 值表示僵尸进程数量，进程状态为 Z 表示僵尸进程。

# 死锁

其实这个和之前Java里面学的差不多，只不过之前Java里面学的是线程问题，对于进程来说，因为相对独立，所以还好，可能就是一些外设什么的是共享的。同步问题和死锁问题肯定都是涉及到公共资源的。

Java 和 操作系统对死锁的视角实际上是高度统一的，因为Java也是得调用操作系统的系统调用。而且Java是 1：1模型，1个Java线程就对应1个操作系统线程。

## 死锁的四个必要条件

- 互斥：资源非共享
- 占有并等待
- 非抢占：资源不能被抢占
- 循环等待：循环等待

## 死锁解决

- **预防：**就是限制死，限制并发进程对资源的请求，0概率发生死锁（破坏必要条件）。
- **避免：**分配资源时，根据使用情况做出预测，避免死锁发生。
- **检测：**发生之后，检测出死锁发生。
- **解除：**与检测配套，将进程从死锁状态下解脱出来。

### 死锁预防

一般是破坏第二个和第四个条件（占有等待 和 循环等待）。

#### 静态分配策略

破坏【占有等待】，就是一开始就等待所有需要的资源都可用了才开始。但是这样会严重影响资源利用率。因为可能有些资源是某个进程后边才要用，或者在某些情况才要用。这段时间，他不用，别的也用不了。

#### 层次分配策略

破坏循环等待，就是一种资源申请的规则，资源被分成多个层次，进程得到某一层次资源后，只能申请更高层次资源。释放某层的资源，必须先释放更高层资源。这样就没有循环等待了。

可以规定所有线程必须按照同样的顺序来获取锁（先 A 后 B），这样就不会出现环路，破坏循环等待。

### 死锁避免

死锁预防就是破坏四个必要条件，但是也可以不破坏，允许四个必要条件存在。因为那四个只是必要条件，不充分。可以在分配的时候选择合理的策略，将系统分为安全/不安全状态。如果在有限时间内所有进程可以得到所有需要的资源，就是安全状态。

比较有代表性的就是 **银行家算法**。

死锁避免 资源利用率提升，但是需要不断尝试计算安全情况，需要花费较多时间。

### 死锁检测

差不多就是乐观锁，死锁发生了再解决。

#### 进程-资源分配图

![image.png](/images/posts/计算机基础-操作系统-进程管理/进程管理-4.png)

进程-资源分配图中存在环路并不一定是发生了死锁。因为循环等待资源仅仅是死锁发生的必要条件，而不是充分条件。

检测流程：

1.  如果进程-资源分配图中无环路，则此时系统没有发生死锁
2.  如果进程-资源分配图中有环路，且每个资源类仅有一个资源，则系统中已经发生了死锁。
3.  如果进程-资源分配图中有环路，且涉及到的资源类有多个资源，此时系统未必会发生死锁。如果能在进程-资源分配图中找出一个 **既不阻塞又非独立的进程** ，该进程能够在有限的时间内归还占有的资源，也就是把边给消除掉了，重复此过程，直到能在有限的时间内 **消除所有的边** ，则不会发生死锁，否则会发生死锁。(消除边的过程类似于 **拓扑排序**)

### 死锁解除

1.  **立即结束所有进程的执行，重新启动操作系统**：这种方法简单，但以前所在的工作全部作废，损失很大。
2.  **撤销涉及死锁的所有进程，解除死锁后继续运行**：这种方法能彻底打破**死锁的循环等待**条件，但将付出很大代价，例如有些进程可能已经计算了很长时间，由于被撤销而使产生的部分结果也被消除了，再重新执行时还要再次进行计算。
3.  **逐个撤销涉及死锁的进程，回收其资源直至死锁解除。**
4.  **抢占资源**：从涉及死锁的一个或几个进程中抢占资源，把夺得的资源再分配给涉及死锁的进程直至死锁解除。

- 为了在多个进程间交换信息，内核专门留出了一块内存区，可以由需要访问的进程将其映射到自己的私有地址空间。进程就可以直接读写这一块内存而不需要进行数据的拷贝，从而大大提高效率。

## 信号量

就是共享内存做同步，相当于加锁。

## Socket

# 进程调度

当CPU空闲时，操作系统选择内存中某个【就绪状态】的进程，将其分配给CPU。

先总结说一下调度算法：

- 先来先服务
- 最短作业优先
- 高响应比优先
- 时间片轮转
- 最高优先级
- 多级反馈队列

## 先来先服务

比较简单，就是按顺序一个一个来，前面的执行完了或者阻塞了，下一个才允许。

看似公平，但是如果前面是长作业就坏了。后面全阻塞了。

## 最短作业优先调度

这个就是第一种的另一端，很可能把长作业饿死。

## 高响应比优先调度算法

就是一种权衡，既考虑到任务本身的长度，又考虑到任务的等待时间。

## 时间片轮转调度

最古老、最简单、最公平、使用最广。

经验来看，将时间片设置为 20ms - 50ms 是一个比较合理的折中值。

## 最高优先级调度算法

就是赋予进程优先级，可以是静态，也可以是动态。

但是也存在问题，也可能会饿死低优先级的进程。

## 多级反馈队列调度算法（现实最常用）

多级队列，前面的优先级高，时间片短。（队列内部FIFO，第一次没执行完就放到后面队列的队尾）

只有前面的队列执行完了，才会执行后面的。

新的进程来了，就放到第一个队列末尾。

如果在后面的执行过程中，有新的进程进入较高队列，就把当前正在运行的放入对应队列队尾，然后先去执行更高优先级的。

- 对于短任务，可能第一次执行就结束了。
- 对于长任务，也不会饿死，因为前面的进程执行是时间有限的。

这个算法兼顾了长短作业，同时有较好的响应时间。

# 僵尸进程和孤儿进程

前置知识：

Unix/Linux 系统中，当一个进程执行 exit() 时，内核会释放该进程的所有资源，包括打开的文件、占用的内存等，但是！PCB依然存在于内存中。需要父进程 wait() 或 waitpid() 释放。

**僵尸进程（Zombie Process）的出现，不是因为操作系统“忘了”删除 PCB，而是出于一个非常重要的设计目的：让父进程有机会获取子进程的退出状态（exit status）**。

**僵尸进程：**子进程已经终止，父进程仍在运行，父进程没有调用 wait() 或 waitpid() 系统调用来回收子进程。

**孤儿进程：**一个进程的父进程已经终止，但是该进程仍在运行。通常是意外终止，未及时调用 wait() 或 waitpid() 回收子进程。操作系统会将孤儿进程的父进程设置为 init 进程，由 init 进程来回收孤儿进程的资源。

linux 可使用 top 命令查找，zombie 值表示僵尸进程数量，进程状态为 Z 表示僵尸进程。

# 死锁

其实这个和之前Java里面学的差不多，只不过之前Java里面学的是线程问题，对于进程来说，因为相对独立，所以还好，可能就是一些外设什么的是共享的。同步问题和死锁问题肯定都是涉及到公共资源的。

Java 和 操作系统对死锁的视角实际上是高度统一的，因为Java也是得调用操作系统的系统调用。而且Java是 1：1模型，1个Java线程就对应1个操作系统线程。

## 死锁的四个必要条件

- 互斥：资源非共享
- 占有并等待
- 非抢占：资源不能被抢占
- 循环等待：循环等待

## 死锁解决

- **预防：**就是限制死，限制并发进程对资源的请求，0概率发生死锁（破坏必要条件）。
- **避免：**分配资源时，根据使用情况做出预测，避免死锁发生。
- **检测：**发生之后，检测出死锁发生。
- **解除：**与检测配套，将进程从死锁状态下解脱出来。

### 死锁预防

一般是破坏第二个和第四个条件（占有等待 和 循环等待）。

#### 静态分配策略

破坏【占有等待】，就是一开始就等待所有需要的资源都可用了才开始。但是这样会严重影响资源利用率。因为可能有些资源是某个进程后边才要用，或者在某些情况才要用。这段时间，他不用，别的也用不了。

#### 层次分配策略

破坏循环等待，就是一种资源申请的规则，资源被分成多个层次，进程得到某一层次资源后，只能申请更高层次资源。释放某层的资源，必须先释放更高层资源。这样就没有循环等待了。

可以规定所有线程必须按照同样的顺序来获取锁（先 A 后 B），这样就不会出现环路，破坏循环等待。

### 死锁避免

死锁预防就是破坏四个必要条件，但是也可以不破坏，允许四个必要条件存在。因为那四个只是必要条件，不充分。可以在分配的时候选择合理的策略，将系统分为安全/不安全状态。如果在有限时间内所有进程可以得到所有需要的资源，就是安全状态。

比较有代表性的就是 **银行家算法**。

死锁避免 资源利用率提升，但是需要不断尝试计算安全情况，需要花费较多时间。

### 死锁检测

差不多就是乐观锁，死锁发生了再解决。

#### 进程-资源分配图

![image.png](/images/posts/计算机基础-操作系统-进程管理/进程管理-4.png)

进程-资源分配图中存在环路并不一定是发生了死锁。因为循环等待资源仅仅是死锁发生的必要条件，而不是充分条件。

检测流程：

1.  如果进程-资源分配图中无环路，则此时系统没有发生死锁
2.  如果进程-资源分配图中有环路，且每个资源类仅有一个资源，则系统中已经发生了死锁。
3.  如果进程-资源分配图中有环路，且涉及到的资源类有多个资源，此时系统未必会发生死锁。如果能在进程-资源分配图中找出一个 **既不阻塞又非独立的进程** ，该进程能够在有限的时间内归还占有的资源，也就是把边给消除掉了，重复此过程，直到能在有限的时间内 **消除所有的边** ，则不会发生死锁，否则会发生死锁。(消除边的过程类似于 **拓扑排序**)

### 死锁解除

1.  **立即结束所有进程的执行，重新启动操作系统**：这种方法简单，但以前所在的工作全部作废，损失很大。
2.  **撤销涉及死锁的所有进程，解除死锁后继续运行**：这种方法能彻底打破**死锁的循环等待**条件，但将付出很大代价，例如有些进程可能已经计算了很长时间，由于被撤销而使产生的部分结果也被消除了，再重新执行时还要再次进行计算。
3.  **逐个撤销涉及死锁的进程，回收其资源直至死锁解除。**
4.  **抢占资源**：从涉及死锁的一个或几个进程中抢占资源，把夺得的资源再分配给涉及死锁的进程直至死锁解除。
