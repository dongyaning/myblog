# 内核

![image.png](/images/posts/计算机基础-操作系统-操作系统结构概览/操作系统结构概览-1.png)

这个图就可以看出来，其实把这个 Kernel 换成 OS 也合理，所以内核就是操作系统核心差不多。

现代操作系统内核核心能力：

- 进程调度，进程线程管理，决定CPU使用归属。
- 内存管理。
- 硬件设备管理。
- 向上提供系统调用。

**大多数操作系统会把内存分为 用户空间 和 内核空间。**

用户空间的代码只能访问一个局部的内存空间，而内核空间的代码可以访问整个内存。

因此，在用户态执行 = 程序使用用户空间（内存）。

应用程序进入内核态需要系统调用，触发中断。

内核程序执行在内核态，用户程序执行在用户态。当应用程序使用系统调用时，会产生一个中断。发生中断后， CPU 会中断当前在执行的用户程序，转而跳转到中断处理程序，也就是开始执行内核程序。内核处理完后，主动触发中断，把 CPU 执行权限交回给用户程序，回到用户态继续工作。

## 为什么不能只有内核态？

主要就是为了安全、稳定、隔离。只有内核态会使得系统的安全降低，有一些操作是不能允许应用进程有访问的可能的，这样可以尽可能地安全。

## 内核切换

1.  **用户程序执行一条特殊的 CPU 指令（如** `**syscall**`**）**  
    → 这不是普通函数调用，而是一条**由 CPU 架构定义的特权切换指令**。
2.  **CPU 的硬件电路（控制单元）检测到该指令，立即触发预定义的硬件行为**

- 自动将 CPU 从 **用户态（低特权级，如 Ring 3 / EL0）切换到内核态（高特权级，如 Ring 0 / EL1）**；
- 根据**操作系统预先写入的寄存器**（如 x86 的 `IA32_LSTAR`，ARM 的 `VBAR_EL1`）， 跳转到**内核中指定的入口地址**；
- 保存返回信息（如用户态下一条指令地址）到特定寄存器或内核栈。

3.  **跳转到的“入口程序”是操作系统内核的一部分**

- 这段代码（如 Linux 的 `entry_SYSCALL_64`）是**内核在启动时就准备好并注册给 CPU 的**；
- 它会：

- 保存完整的用户上下文（寄存器状态）；
- 从寄存器中读取**系统调用号**和**参数**；
- 根据调用号查表（如 `sys_call_table`），**分发到对应的内核处理函数**（如 `sys_read`, `sys_write`）；
- 执行具体的内核逻辑（访问设备、操作页表、调度等）。

4.  **执行完毕后，内核调用返回指令（如** `**sysret**` **/** `**eret**`**）**

- CPU 硬件再次介入：

- 恢复用户态特权级；
- 恢复用户程序的指令指针和栈；
- **切换回用户地址空间的上下文**（虽然虚拟地址空间可能共享，但权限位确保隔离）。

5.  **用户程序继续执行，仿佛调用了一个普通函数**

- 实际上经历了完整的**用户态 → 内核态 → 用户态**切换。

所以说这个的流程是：用户程序直接执行CPU指令，CPU电路逻辑直接实现内核态切换，处理内核态切换的内核程序是预先设定好的，这个程序可以根据不同的系统调用选择不同的处理逻辑。处理完了之后再返回。也就是说内核态CPU状态不同，可用的内存空间也不同，是和用户态隔离开的两个区域。

## 切换内核态的三种方式

- 系统调用
- 中断
- 异常
